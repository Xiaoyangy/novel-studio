# Readiness 事务与真实历史对照

本次优化减少一次章节就绪评估内部的重复历史回放，不减少正式评估次数，也不改变文学质量或硬合同标准。

## 执行路径

旧 verified 路径在控制器取末周期、准备输入、读取已有审计、保存审计、重读结果及应用游标时，分别完整重建来源链。

新 V2/V3 verified 路径分成两个短事务：

1. `PrepareVerifiedCharacterReadinessReview` 在同一读锁内验证当前来源链，构建精确评估输入并检查已有审计。
2. 模型在锁外提交原协议的结构化判断。
3. `CommitVerifiedCharacterReadinessReview` 重新读取并验证来源链，核对输入、模型视图、CAS 与原判断，依次保存 audit、readiness、session。

准备阶段的内存对象不是提交阶段的信任凭据；没有跨调用缓存，也不持元数据锁等待模型。提交后控制器按原 domain 状态转移核对返回会话，不再为取回本次结果额外回放历史。

## 恢复与兼容

- 保存了 audit 但后续写入失败时，恢复复用该真实判断；预算到期不阻止不调用模型的机械补交。
- 只有确需新模型请求时才进入派发门禁，逐请求预算检查不变。
- 重复提交必须与原磁盘 audit/receipt 完全一致；CAS 冲突、来源变化或模型视图篡改仍拒绝。
- 在途合法结果仍可持久化；无结构化提交、错误返回游标或预算耗尽均不能伪装成 ready。
- 旧 generic/legacy API 保留，既有 receipt、schema、prompt、producer 摘要和封存验证规则不变。未引入宿主自动判定 ready 或跳过评估的协议。

## 2026-09-13 单次真实历史对照

使用原失败样例第2章已闭合的25周期证据，在独立文件副本中重建最后一次评估前的状态，并重放其真实已存裁决；原小说内容根保持不变，不调用模型、不产生新正文。

| 路径 | 本地耗时 | 累计分配字节 | 完整来源回放 |
| --- | ---: | ---: | ---: |
| 原调用组合 | 188.591秒 | 163.151 GB | 6次 |
| 事务组合 | 67.180秒 | 54.771 GB | 2次 |

Apple M1 Pro 上该单次对照耗时减少约64.4%，累计分配减少约66.4%。评估输入、原裁决回执、最终 session 及三个持久文件保持相同。这是评估阶段的本地处理数据，不包含模型等待，不是单章或全书加速比例，也不是20分钟交付达标证明。

基准为 `BenchmarkCharacterReadinessTransactionReplay`，显式沿用 `NOVEL_STUDIO_ACTIVATION_AUDIT_OUTPUT/GENERATION/CHAPTER` 选择证据，必须使用 `-run '^$' -benchtime=1x`。无显式来源时跳过；所有试验写入限于测试临时副本。
