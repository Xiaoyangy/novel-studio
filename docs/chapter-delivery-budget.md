# 章节交付墙钟预算

该功能用于记录并约束时间，不保证小说一定在时限内达到质量要求。**超时停止是未达标，不是已交付。**

在新 planning generation 创建前显式配置：

```json
{
  "budget": {
    "chapter_delivery_seconds": 1200
  }
}
```

允许 1–86400 秒，0 表示新代次不启用。金额预算 `book_usd`、`warn_ratio`、`hard_stop` 保持原有独立语义；不需要设置金额预算才能启用墙钟预算。

## 计时口径

- 起点是本章首次细推派发，终点必须绑定实际正文、审核和 outcome 的正式验收回执。
- 三章窗口内，每个已开始但尚未验收的章节都持续计时。检查的是同书最早未完成期限，不仅是当前正在工作的章节。
- 前三章细推等待、模型调用、工具重试、本地验证、正文与返工都计入；暂停、重启和恢复不会把起点清零。
- 初始化和整弧预演的启动成本另报，也应同时报告新书启动至首章正文的总等待，不用热启动成绩冒充完整启动成绩。

## 到期与恢复

到期后拒绝新的宿主模型派发。已经在途的调用仍按原协议返回、验证和保存；必要的机械恢复仍可执行。有效提案、待审正文、反馈和用量记录不会仅因这一时间期限被清退。真实源错误、用户取消或独立金额预算仍按各自原规则处理。

晚到的验收仍保留真实结果，但不能算作时限内交付。如果验收已落盘、计时收口前发生崩溃，恢复必须重新核验相应证据，并标记原完成时间无法确证；不能拿较早的模型结束时间或 outcome 时间回填。

预算政策冻结在 generation 中，运行记录位于 live 书目 `meta/runtime/chapter_delivery/ledger.json`，不放进可丢弃的投影工作区。旧代次没有标记时保持原协议，不给旧过程虚构起点。已启用代次不能通过修改配置、换 stages 或创建覆盖代次洗掉时间记录。

当前机制不会自动重新授予超时章节一个新期限。失败样例应保留用于定位和对照；新的性能实验应作为明确的新尝试保存，不能把旧样例续跑后的总时间改记成 20 分钟。

## 判定达标

字数、角色自主决策、知识边界、硬合同和审核要求均不降低。只有该正文版本真正通过验收且计时证据完整，才能报告它是否在预算内完成。停止于预算错误、只生成计划、或有模型回复但尚未落盘，均不是达标证据。
